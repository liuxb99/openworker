## 6. 缺口六：PowerShell UTF-8 BOM 令 REAL receipt 被 Go JSON reader 誤判無效

fresh v5 run `32200467037`、O87 job `95913004227` 已真正執行 `Verify REAL four-slot local supervisor`。

REAL smoke 已成功證明：

- `distinct claim workers = 4`
- `distinct executor slots = 4`
- LOCAL_SUPERVISOR route 成立
- 五個 smoke work 均完成

但驗收最後回報：

```text
REAL smoke passed but local supervisor is not OPERATIONAL:
claim=4 executor=4 status=NOT_VERIFIED
```

根因：Windows PowerShell 5.1 的 `Set-Content -Encoding utf8` 會在 `true-local-supervisor-real-verification.json` 開頭寫 UTF-8 BOM；Go `encoding/json.Unmarshal` 原本直接讀 bytes，不接受該 BOM，因此 `localSupervisorVerificationSnapshot()` 將有效 REAL receipt 誤判為 invalid / NOT_VERIFIED。

修復：

- `da6cac488132fc78b3e0d880eeb654447f1c1c3d`：Go reader 先移除 UTF-8 BOM，再做 JSON parse，兼容既有 Windows receipt。
- `938a3c0b3ee5396e9adbabbcbf3f1aaca7d1fb43`：新增帶 BOM receipt 的回歸測試。
- `aa0df0ffbab2e7851c87b97800de9b701d609bd6`：PowerShell verifier 改用 `[Text.UTF8Encoding]::new($false)` 無 BOM 寫檔，並在 OPERATIONAL 失敗時輸出 verification / capability authority reason。

修復後已自動觸發新 O87 deployment run `32200560611`，O87 job `95913280903` 已通過 build/install/bootstrap/control-plane，正在執行 fresh REAL 4+4 驗收。
