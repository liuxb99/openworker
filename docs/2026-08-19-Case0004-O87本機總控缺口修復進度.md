## 5. 缺口四：REAL runner 上 unit test 污染了 installed authority

### REAL 現象

包含缺口三修復的新 O87 deployment run `32199423350` 已明確 checkout `62b5f4a...`，但 targeted tests 在 `TestLocalWorkHandlerAllowsCentralSubmitToODAAndRejectsWrongClaim` 失敗：

```text
submit status=503
assigned_host=DESKTOP-ODAQN0D
reason=assigned_host does not match this local queue authority
registered_capabilities=[go-tool.local-supervisor.smoke go-tool.runtime.update-local go-tool.supervisor.probe]
```

這次不是產品 runtime route 錯，而是測試環境錯：該 generic queue unit test 寫死 ODA hostname，但在 O87 REAL resident runner 上執行時會讀到 O87 的 `ProgramData\go-tool-runtime\work-agent\local-queue-authority.json`。新增的 installed-capability fail-closed 邏輯因此正確地拒絕 ODA submit，反而使原本應只測 queue semantics 的 unit test 被本機已安裝狀態污染。

### 修復原則

不能放寬 production fail-closed。production 仍必須：

- hostname 不符即拒絕；
- capability 未由 installed executor contract 註冊即拒絕；
- 禁止 GitHub business fallback。

應修的是 unit test isolation。

### 修復

- repo：liuxb99/go-tool-runtime
- commit：`275577ba67e20b9a0fac3d6d66c0e6d5990e08c6`
- `TestLocalWorkHandlerAllowsCentralSubmitToODAAndRejectsWrongClaim` 在測試內把 `ProgramData` 指向 `t.TempDir()`，確保 generic durable queue semantics 不讀 REAL runner 的 installed authority。
- 專門驗證 installed authority fail-closed 的測試仍保留自己的 authority fixture，不降低 production gate。

另外，`6c513f50fd8df28d066671a098a39ae55f90100a` 已補 capability authority contract tests，鎖住 wrong-host / unknown-capability 必須 fail-closed。

## 6. 競跑與 evidence 判讀

部署 workflow 會在 start marker 階段推 evidence commit，且多台機器可同時推 marker，因此 main 會快速前進。驗證不能只看 workflow 起始 SHA；必須看 `Refresh checkout after evidence attempt` 後實際 HEAD 與 log 中執行的 source contract。

舊 rerun 若仍顯示舊 installer / 舊測試，不可用來否定較新的 source 修復。只有實際 checkout 到對應修復 commit 或其後繼 main 的 run 才算有效驗證。
