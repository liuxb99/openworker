## 9. 缺口九：任一 claim slot 瞬時 loopback 斷線會拖死整個 4-slot agent

O87 多輪 log 都曾出現：

```text
runner heartbeat ... connection forcibly closed
claim ... connection forcibly closed
runner heartbeat ... EOF
```

檢查 `cmd/gtr-work-agent/main.go` 發現，原設計任何一個 slot 的 `workerLoop` 回傳 error 都會送入共用 `errCh`，main 收到第一個 error 就 `fatalf`，因此單一瞬時 HTTP/loopback 錯誤可能把整個四槽 claim-agent 進程殺掉。這與 REAL smoke 後 heartbeat / OPERATIONAL 不穩定高度吻合。

修復 commit：`c6dbd7df4f08463637da5bbb30abf469a1929d15`。

新設計：

- transport / timeout / EOF / connection reset / HTTP 408/429/5xx 視為 transient control-plane failure；
- 單 slot 以 1s → 2s → 4s → 5s capped backoff 重連；
- wrong-host、durable spool 寫入、invalid identity 等 semantic/invariant failure 仍 fail-closed；
- `--once` 模式仍直接回錯，方便測試與驗收；
- 不因單一 transient slot error 讓四個 claim slots 全部死亡。

executor 的 exactly-once / side-effect retry 語義不在這一批冒然放寬；它仍由 durable claim、execution lock、result/error evidence 保護，後續只有在 REAL 證據顯示 executor 也因同類瞬斷失效時再做精確修復。
