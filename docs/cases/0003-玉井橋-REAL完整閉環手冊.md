## 0. OpenWorker 執行原則

本案例是 OpenWorker 的工作手冊，不只是平台進度摘要。OpenWorker 接手時必須先讀本文件，再讀各 owning repo 的實際 contract / workflow / capability，不得憑記憶猜路徑或另造第二套流程。

執行規則：

1. 一次只推進目前真正 blocker，不重跑已成功且昂貴的 REAL 工作。
2. 發現缺口時修真正 owning repo，再回到同一路徑重跑。
3. 所有工具使用最新 `main` 提交；workflow 需 checkout 最新 owning repo / OpenWorker / go-tool-runtime。
4. 對共享 DTM、GPU、ComfyUI、Blender、Godot 等本機資源避免競爭 run。
5. 任何 workspace artifact 必須檢查：存在、非零、正確路徑、必要時 SHA256 / size / mtime。
6. 路徑與 workspace contract 必須 fail-closed；禁止 path traversal 或 workspace escape。
7. GitHub Actions matrix 中非 business runner 的 route/skip job 不可算產品成功。
8. GitHub Actions artifact quota 只屬 evidence upload 基礎設施問題；必須與 product gate 分開判讀。
9. 每完成一批，要把 run/job/commit/產物/缺口/下一步同步更新本手冊。

## 8. Step G：Review canonical-current-artifact gate

### G-1 已發現的真實缺口

舊版 `review.Status()` 直接對 `artifacts.ListByJob(ctx, jobID)` 的所有歷史 artifacts 做 approval gate。

錯誤結果：

- revision 1 已被 revision 2 取代。
- 即使 revision 2 已 approved，revision 1 的 rejected/rework 仍會阻塞 Delivery。

### G-2 正確語意

Review 先按以下 key 壓成 current set：

`(component_id, kind)`

只選最高 `Revision` 參與 approval gate。

歷史 revision：

- 保留。
- 可追溯。
- 不阻塞 current publish。

### G-3 已修補

- implementation：`7967b477f8849603e942d6e0453727a49a488824`
- regression tests：`1e312ada248ce7ba9af5b3cd7a41ef324f6c210d`

永久 regression cases：

1. old revision = rejected/rework；latest = approved → latest 必須能 publish。
2. old revision = approved；newer revision 尚未 review → newer 必須被阻塞，不能沿用舊 approval。
