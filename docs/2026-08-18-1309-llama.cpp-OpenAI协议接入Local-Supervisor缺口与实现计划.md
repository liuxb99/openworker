## 5. Bootstrap Contract 已实现

每次 Host 新进程创建新的随机 `session_id`。第一次模型请求之前严格执行：

```text
supervisor_session
-> supervisor_recover
-> supervisor_attention
-> supervisor_jobs
-> cluster_agents
-> cluster_capabilities
```

模型收到的是启动事实快照，但 system contract 明确要求：这些只是 bootstrap facts，当前 authority 仍要通过工具查询 OpenWorker durable state。

## 6. Supervisor System Contract 已固化

`SUPERVISOR_SYSTEM_CONTRACT` 固定约束：

- Local Coder 是 Supervisor，不是 worker；
- OpenWorker 是 job/process/queue/lock/progress/artifact/QC 的 durable authority；
- 禁止自己用 shell / Start-Process 管理长任务；
- 禁止自己维护 PID / 第二套 queue / scheduler；
- `job_submit` durable ACK 后不得阻塞等待业务 job；
- `Action completed != job succeeded`；
- fixed-machine job 不得漂移；
- failed/timed_out/stale/blocked 先查 durable fact / failure knowledge；
- decision receipt 不保存 chain-of-thought；
- tool error 不能猜成成功。

## 8. Tool-call Agent Loop 已实现

```text
messages + tools
-> llama.cpp chat.completions
-> assistant tool_calls
-> Local Supervisor Host dispatch
-> append role=tool + tool_call_id
-> llama.cpp continuation
-> until no tool_calls
```

支持一次 assistant response 内多个 tool calls。

加入：

```text
max_tool_rounds
```

超过上限直接失败，避免模型无限工具循环。

Tool arguments：

```text
malformed JSON -> fail-closed
non-object args -> fail-closed
unknown tool -> fail-closed
missing required argument -> fail-closed
invalid drain mode -> fail-closed
```

运行 loop 中的 tool failure 会以：

```json
{"ok": false, "error": "...", "tool": "..."}
```

回传给模型，让模型能 replan，但绝不把失败当成功。

## 9. Heartbeat / 非阻塞观察

Host 有：

```text

```

长任务本身不在 OpenAI request 内等待。模型拿到 durable ACK 后继续处理别的工作；下一次 turn / attention observation 再读取当前状态。


## 14. 当前架构结果

现在已经形成：

```text
llama-server.exe
      |
      | OpenAI-compatible /v1
      v
coworker.local_supervisor
      |
      | OpenAI function tools
      v
OpenWorkerNodeClient
      |
      v
OpenWorker durable Supervisor / jobs / cluster
```

所以本机模型不需要永久记住 OpenWorker 架构；每次 Host 启动都会重新建立 session、recover durable state、注入 Supervisor Contract，再通过工具取得实时 authority。
