## 4. Definition Refresh：長跑 Case 不再靠重新 Bootstrap 更新

這是新版做法的重要改變。

問題：ODA workspace 在 revision 14 bootstrap 時已保存 `.openworker/case-worklist.json`。後續 Git source worklist 增加 `fanout_role`、typed presentation metadata 等欄位時，若直接重新 bootstrap，可能破壞已存在的 `0005-010` durable work reference 與 runtime evidence。

新版解法：每次合法 `case continue` 前先執行 **safe definition refresh**。

Refresh 規則：

- 保留既有 step `status / evidence / blocker`。
- 保留目前 controller durable `work_id`。
- 禁止刪除 runtime 已存在 step。
- 禁止修改 terminal-success step 的 execution contract。
- 禁止修改目前 active work step 的 execution contract。
- 未開始的未來 step 可以更新，但 structural change 必須提升 revision。
- spec 變更也必須提升 revision。
- path 仍受 `openworker_root` containment 保護。

因此 Case0005 source authority 已安全升為 **revision 15**，但既有 `0005-010-r000014-...` 不會被重建或改 ID。revision 15 主要讓未來步驟取得新版 metadata。
