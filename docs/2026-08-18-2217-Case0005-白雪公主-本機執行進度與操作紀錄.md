### 5.2 找到真实 readback 缺口根因

仓库原本已经存在 `.github/workflows/dispatch-local-supervisor-command-oda.yml`，并在 commit `7a04fb1fbf4402e79674e509ef2615d7929d8a13` 加入 `command-results/oda.json` 回写逻辑。

但进一步检查发现两个关键问题：

1. `invoke-local-supervisor-command-transport.ps1` 在 openworkerctl 失败 / reject 时直接 throw，因此 workflow 还没写 `command-results/oda.json` 就终止，导致 ChatGPT 永远只看到 404，无法区分「runner 没接单」和「本机 transport 拒绝」。
2. workflow 的 concurrency group 原为 `openworker-command-transport-oda-${{ github.run_id }}`。因为每个 run_id 都不同，实际上没有形成 ODA command transport 串行队列，多个 request 理论上可同时进入。

### 5.3 已完成修复

#### A. transport wrapper：失败也先生成 receipt

Commit：`91471dc024251ddfe05a8856172f8be35c7c9a73`

修复：

- 所有 bounded command 输出统一 `openworker.command-transport.v1`。
- openworkerctl 不存在、非 JSON、exit != 0、`case_continue` 未返回 accepted=true，都不再在 receipt 产生前丢失状态。
- receipt 新增 `accepted / exit_code / error / result`。
- receipt 明确：
  - `github_action_used_for_command_transport=true`
  - `github_action_used_for_business_execution=false`
  - `business_completion_claimed=false`
  - `authoritative_business_state=openworker`
- 每个 `request_id` 在 ODA 本机持久化至 `%ProgramData%\OpenWorker\command-transport\receipts\<request_id>.json`。
- workflow rerun 遇到相同 request_id 时直接回放缓存 receipt，不重复执行本机命令。

#### B. workflow：真正串行 + 先发布失败 receipt 再 fail

Commit：`d4445e7e12e83f7a98fa451016f1c8922fe2c38c`

修复：

- concurrency group 改为固定 `openworker-command-transport-oda`。
- `cancel-in-progress=false`，让 ODA 高阶控制命令顺序执行。
- push request 增加 schema、machine、case_id、requested_by、request_id fail-closed 验证。
- workflow 不再要求 `receipt.accepted=true` 后才写回 Git。
- 无论 accepted/rejected，都先生成并提交 `command-results/oda.json`。
- 回执提交完成后，若 `accepted=false`，最后一步才让 workflow fail，确保 ChatGPT 一定能读到失败原因。
