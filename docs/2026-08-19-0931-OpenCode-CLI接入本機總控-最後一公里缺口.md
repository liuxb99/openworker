## 目的

補上 ChatGPT 與 ODA 本機總控之間的最後一公里，同時維持既有 authority 分工，絕不把 GitHub Actions 重新當成 Case 業務執行橋樑。

目前目標鏈路：

`ChatGPT / OpenAI Remote MCP -> OpenAI Secure MCP Tunnel -> ODA OpenCode MCP Bridge -> ODA OpenCode Server -> openworkerctl -> 127.0.0.1:8848 -> go-tool durable local queue -> OpenWorker 本機總控 -> 4-slot Action -> Google Drive -> ChatGPT 實體成果審查`

## 已完成且不得重做

1. Case 0005 固定 `DESKTOP-ODAQN0D`，機器權威是 `COMPUTERNAME`。
2. go-tool-runtime `:8848` 是 durable queue / local supervisor authority。
3. OpenWorker 是 Case progress / execution truth authority。
4. claim/executor 目標為 4 + 4 fresh slots。
5. GitHub Actions 只允許 code update / repair；禁止 Case business execution、status transport、artifact transport。
6. ODA 直接用 Google Drive API 發布成果；ChatGPT 從 Drive 取回 PPTX / JPG / MP4 審查。
7. Case 成功必須有完整 append-only supervisor ledger。

## 本批新增：Remote readiness 已綁定 Case durable ledger

先前 `REMOTE_TRANSPORT_READY` 只存在 `%ProgramData%` runtime receipt，這仍不足以成為 Case 本身的 durable evidence。本批已修正：

`scripts/activate-case0005-secure-mcp-remote.ps1` 現在會：

1. 不只檢查子腳本 exit code，還會解析每一步 JSON receipt。
2. 強制驗證 OpenCode bridge `LOCAL_READY`。
3. 強制驗證 OpenCode bridge `LOCAL_VERIFIED`。
4. 強制驗證 tunnel runtime `READY` 且 tunnel_id 完全一致。
5. 強制驗證 tunnel `TUNNEL_VERIFIED` 且 tunnel_id 完全一致。
6. 將 `REMOTE_TRANSPORT_READY` receipt 同時寫入：
   - `%ProgramData%\OpenWorker\secure-mcp-tunnel\case0005-remote-activation.json`
   - `D:\AI-Work\jobs\0005-SNOW-WHITE\.openworker\secure-mcp-remote-activation.json`
7. 向 Case authoritative append-only ledger：
   `D:\AI-Work\jobs\0005-SNOW-WHITE\.openworker\case-supervisor-ledger.jsonl`
   append `remote_transport_ready` event。
8. ledger event 綁定 `case_id=0005`、ODA machine、workspace、tunnel_id、bridge verification status、tunnel verification status，並明確記錄 `github_action_used_for_business_execution=false`。

因此未來不能只拿 tunnel daemon 的 log 就宣稱 Case remote control 成功；必須在 Case ledger 裡看到對應 durable event。

對應 contract test 已同步更新：`tests/test_case0005_opencode_secure_tunnel_contract.py`。
