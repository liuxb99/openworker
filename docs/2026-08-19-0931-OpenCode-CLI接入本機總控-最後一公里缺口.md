# OpenCode CLI 接入本機總控：最後一公里缺口

時間：2026-08-19 09:31 +08:00

## 目的

補上目前 ChatGPT 與 ODA 本機總控之間的最後一公里，但不把 GitHub Actions 重新當成業務執行橋樑。

目標鏈路：

`ChatGPT / OpenCode 上層指令 -> ODA OpenCode CLI -> openworkerctl -> 127.0.0.1:8848 -> go-tool durable local queue -> OpenWorker 本機總控 -> 4-slot Action -> Google Drive -> ChatGPT 實體成果審查`

## 已經完成、不得重做的部分

1. Case 0005 已固定 `DESKTOP-ODAQN0D`，機器權威是 `COMPUTERNAME`。
2. go-tool-runtime `:8848` 是 durable queue / local supervisor authority。
3. OpenWorker 是 Case progress / execution truth authority。
4. 本機 claim/executor 目標均為 4 slots。
5. GitHub Actions 只允許 code update / repair，不允許 Case business execution、status transport、artifact transport。
6. 成果由 ODA 直接用 Google Drive API 發布；ChatGPT 從 Drive 取回 PPTX / 圖片 / MP4 審查。
7. Case 0005 已要求完整 append-only supervisor ledger 才能算成功。

## 現在真正的缺口

不是「如何固定 ODA」，也不是「如何再做一套 queue」。缺的是一個 CLI-neutral、可由 OpenCode CLI 安全呼叫的薄控制層。

目前若讓 OpenCode 自己拼 REST / PowerShell：

- 模型可能拼錯 endpoint / payload；
- 不同 CLI 會各自形成一套控制語法；
- 容易繞過 OpenWorker authority；
- status / clear / continue 的輸出不一定穩定，難以讓上層模型可靠解析；
- 之後換 Codex / Claude Code / llama.cpp Coder 又要重寫提示詞。

## 補缺口方案：`openworkerctl`

在 OpenWorker repo 提供一個很薄的本機 CLI。它不執行業務工具，只負責呼叫既有本機總控 API。

第一批固定命令：

```text
openworkerctl supervisor status
openworkerctl case status 0005
openworkerctl case continue 0005 --machine DESKTOP-ODAQN0D
openworkerctl queue clear --machine DESKTOP-ODAQN0D
```

### 原則

1. 預設 server 只指向 `http://127.0.0.1:8848`。
2. `case continue` 必須要求/驗證 machine，且 Case manifest 的 assigned machine 必須一致。
3. 不提供任意 URL、任意 shell、任意 capability、任意 JSON passthrough。
4. 所有輸出提供穩定 JSON，讓 OpenCode/其他 CLI 可機器解析。
5. `case continue` 只負責喚醒/驅動 canonical controller，不自己執行 Action。
6. `queue clear` 使用既有一鍵清隊列能力；不能靠模型自行判斷逐筆刪除。
7. status 仍以 OpenWorker / local supervisor durable evidence 為準。
8. 不新增 GitHub Action fallback。

## OpenCode 的角色

OpenCode 不是新的總控 authority，只是本機入口/代理：

`OpenCode -> openworkerctl`

OpenCode 不應直接：

- 決定 Action 執行順序；
- 自己維護 Case 狀態；
- 自己宣稱 Case 成功；
- 搬運成果到 GitHub；
- 取代 WorkLedger / Engineering OS / Drive review gate。

## OpenCode 操作規約

給 OpenCode 的規約應盡量短：

1. Case 工作只呼叫 `openworkerctl`。
2. 先 `supervisor status`，必須看到 `OPERATIONAL`。
3. 再 `case continue <case>`。
4. 查進度只用 `case status <case>`。
5. queue 阻塞時只用 `queue clear` 一鍵清理，再 `case continue`。
6. 不以 OpenCode 自己的 terminal output 取代 `.openworker` ledger。
7. 看到 Drive review gate 時停止業務推進，等待 review receipt；receipt PASS 後本機總控自動續跑。
