## 目的

補上目前 ChatGPT 與 ODA 本機總控之間的最後一公里，但不把 GitHub Actions 重新當成業務執行橋樑。

目前目標鏈路已收斂為：

`ChatGPT / OpenAI Remote MCP -> OpenAI Secure MCP Tunnel -> ODA OpenCode MCP Bridge -> ODA OpenCode Server -> openworkerctl -> 127.0.0.1:8848 -> go-tool durable local queue -> OpenWorker 本機總控 -> 4-slot Action -> Google Drive -> ChatGPT 實體成果審查`

## 已經完成、不得重做的部分

1. Case 0005 已固定 `DESKTOP-ODAQN0D`，機器權威是 `COMPUTERNAME`。
2. go-tool-runtime `:8848` 是 durable queue / local supervisor authority。
3. OpenWorker 是 Case progress / execution truth authority。
4. 本機 claim/executor 目標均為 4 slots。
5. GitHub Actions 只允許 code update / repair，不允許 Case business execution、status transport、artifact transport。
6. 成果由 ODA 直接用 Google Drive API 發布；ChatGPT 從 Drive 取回 PPTX / 圖片 / MP4 審查。
7. Case 0005 已要求完整 append-only supervisor ledger 才能算成功。

固定命令：

```text

```

控制原則：

1. 預設 server 只允許 `http://127.0.0.1:8848` / localhost:8848。
2. Case 0005 固定 `DESKTOP-ODAQN0D`，錯 machine fail-closed。
3. 不提供任意 URL、任意 shell、任意 capability、任意 JSON passthrough。
4. status 仍以 OpenWorker durable ledger 為準。
5. `case continue` 只驅動 canonical controller，不自行執行業務 Action。
6. `queue clear` 只呼叫既有 `/api/execution/local-work/clear` 一鍵清隊列能力。
7. 不新增 GitHub Action fallback。

Remote MCP 只暴露四個 allowlisted tools：

```text
supervisor_status
case_status
case_continue
queue_clear
```

實際執行鏈不是 MCP 直接跑任意 shell，而是：

`MCP tool -> localhost OpenCode /session/:id/shell -> 固定 openworkerctl.exe -> go-tool :8848`

因此 OpenCode 仍然是本機入口，OpenWorker/go-tool 才是 authority。

### MCP 協議收口

- 協議版本固定為 `2025-06-18`。
- `POST /mcp` 接受 JSON-RPC request/notification。
- `GET /mcp` 明確回 405，表示此 server 不提供獨立 SSE stream；這符合 Streamable HTTP 的無 SSE 模式。
- `DELETE /mcp` 回 405，因 bridge 本身不維護 MCP session state。
- 驗證 `Origin`，拒絕非 localhost browser origin，避免 DNS rebinding 類風險。
- `Accept` 若有提供，必須同時包含 `application/json` 與 `text/event-stream`。

### 安全邊界

- OpenCode server 只監聽 `127.0.0.1:4096`。
- OpenCode server 強制 Basic Auth。
- MCP bridge 只監聽 `127.0.0.1:8850`。
- MCP bridge 強制 Bearer Token。
- MCP 不暴露任意 shell。
- MCP 不允許任意 Case；目前只允許 0005。
- MCP 不允許任意 machine；queue clear 只允許 `DESKTOP-ODAQN0D`。
- MCP 不允許 GitHub business execution。
- 遠端不得直接公開 OpenCode 4096 或 go-tool 8848。

### 安裝方式

`tunnel-client` 不使用不透明第三方 binary 作為唯一來源。安裝腳本會：

1. clone 官方 `openai/tunnel-client` 原始碼；
2. 預設 pin `v0.0.10` stable tag；
3. 驗證 tag commit = checkout HEAD；
4. 從 source 執行 `go build ./cmd/client`；
5. 落盤 install receipt，包含 source repo / tag / commit / exe path。

因此 tunnel client 也可以直接看源碼、固定版本、重新編譯。

### Tunnel runtime

ODA 只做 outbound HTTPS，不開 inbound firewall：

`OpenAI tunnel control plane <- outbound HTTPS poll -> ODA tunnel-client -> http://127.0.0.1:8850/mcp`

`tunnel-client` 對 localhost MCP 的 Bearer token 只透過環境變數 reference 傳入：

```text
MCP_EXTRA_HEADERS=Authorization: env:OPENWORKER_MCP_AUTH
MCP_DISCOVERY_EXTRA_HEADERS=Authorization: env:OPENWORKER_MCP_AUTH
```

不把 token 直接寫在 argv、Git 或 tunnel receipt。

長期 daemon 使用的 OpenAI key 也要求：

- `CONTROL_PLANE_API_KEY`
- restricted runtime key
- 權限只需 Tunnels Read + Use
- 不使用 Admin key 跑 daemon

### 一鍵 ODA 入口

```powershell
$env:CONTROL_PLANE_TUNNEL_ID='tunnel_<32hex>'
$env:CONTROL_PLANE_API_KEY='sk-...'
powershell -ExecutionPolicy Bypass -File scripts\activate-case0005-secure-mcp-remote.ps1
```

該入口依序：

1. 確認/啟動 Case 0005 本機總控；
2. 編譯安裝 OpenCode bridge；
3. 啟動 OpenCode + localhost MCP bridge；
4. 本機 MCP read verification；
5. 從官方 source 編譯 Secure MCP Tunnel client；
6. 啟動 outbound-only tunnel；
7. 驗證 `/healthz`、`/readyz` 與 control-plane tunnel metadata；
8. 落盤 `REMOTE_TRANSPORT_READY` receipt。

## OpenCode 的角色

OpenCode 不是新的總控 authority，只是本機入口/代理。OpenCode 不應直接：

- 決定 Action 執行順序；
- 自己維護 Case 狀態；
- 自己宣稱 Case 成功；
- 搬運成果到 GitHub；
- 取代 WorkLedger / Engineering OS / Drive review gate。

## 現在剩下的 REAL 缺口

### A. ODA 實機部署與 receipt

目前 Secure MCP Tunnel、OpenCode bridge、openworkerctl 都是 source closure。尚未由 ODA 實機執行最新腳本並產生：

- OpenCode bridge `LOCAL_VERIFIED`
- Secure MCP Tunnel `TUNNEL_VERIFIED`
- Case 0005 `REMOTE_TRANSPORT_READY`

因此現在仍不能宣稱 ODA remote control 已 REAL 成功。

### B. OpenAI/ChatGPT 產品端權限

Secure MCP Tunnel 已是正確的 private-network transport，不需要把 localhost MCP 公開到 Internet。

但 ChatGPT 端能否直接呼叫 `case_continue` 仍取決於帳號/Workspace 是否具備 custom MCP write/modify 權限。若產品端只有 read/fetch MCP，則 `supervisor_status` / `case_status` 可作為讀取路徑，但 `case_continue` / `queue_clear` 不能假裝可用。

這是產品 entitlement，不是 OpenWorker 代碼缺口。
