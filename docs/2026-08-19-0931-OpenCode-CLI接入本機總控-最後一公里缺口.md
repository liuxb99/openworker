# OpenCode CLI 接入本機總控：最後一公里缺口

時間：2026-08-19 09:31 +08:00
最後更新：2026-08-19 09:55 +08:00

## 目的

補上目前 ChatGPT 與 ODA 本機總控之間的最後一公里，但不把 GitHub Actions 重新當成業務執行橋樑。

目前目標鏈路已收斂為：

`ChatGPT -> Remote MCP -> ODA OpenCode Server -> openworkerctl -> 127.0.0.1:8848 -> go-tool durable local queue -> OpenWorker 本機總控 -> 4-slot Action -> Google Drive -> ChatGPT 實體成果審查`

## 已經完成、不得重做的部分

1. Case 0005 已固定 `DESKTOP-ODAQN0D`，機器權威是 `COMPUTERNAME`。
2. go-tool-runtime `:8848` 是 durable queue / local supervisor authority。
3. OpenWorker 是 Case progress / execution truth authority。
4. 本機 claim/executor 目標均為 4 slots。
5. GitHub Actions 只允許 code update / repair，不允許 Case business execution、status transport、artifact transport。
6. 成果由 ODA 直接用 Google Drive API 發布；ChatGPT 從 Drive 取回 PPTX / 圖片 / MP4 審查。
7. Case 0005 已要求完整 append-only supervisor ledger 才能算成功。

## 第一層缺口：CLI-neutral 控制層 —— 已完成代碼收口

已新增：

- `go-runtime/cmd/openworkerctl/main.go`
- `go-runtime/cmd/openworkerctl/main_test.go`
- `scripts/install-openworkerctl.ps1`
- `docs/OpenCode-本機總控操作規約.md`

固定命令：

```text
openworkerctl supervisor status
openworkerctl case status 0005
openworkerctl case continue 0005
openworkerctl queue clear DESKTOP-ODAQN0D
```

控制原則：

1. 預設 server 只允許 `http://127.0.0.1:8848` / localhost:8848。
2. Case 0005 固定 `DESKTOP-ODAQN0D`，錯 machine fail-closed。
3. 不提供任意 URL、任意 shell、任意 capability、任意 JSON passthrough。
4. status 仍以 OpenWorker durable ledger 為準。
5. `case continue` 只驅動 canonical controller，不自行執行業務 Action。
6. `queue clear` 只呼叫既有 `/api/execution/local-work/clear` 一鍵清隊列能力。
7. 不新增 GitHub Action fallback。

## 第二層缺口：ChatGPT → ODA OpenCode Remote Bridge —— 已完成本機代碼收口

已新增：

- `scripts/install-openworker-opencode-bridge.ps1`

- `scripts/verify-openworker-opencode-bridge.ps1`
- `docs/2026-08-19-0945-ChatGPT-OpenCode-Remote-Bridge缺口.md`

Remote MCP 只暴露四個 allowlisted tools：

```text
supervisor_status
case_status
case_continue
queue_clear
```

實際執行鏈不是 MCP 直接跑 shell，而是：

`MCP tool -> localhost OpenCode /session/:id/shell -> 固定 openworkerctl.exe -> go-tool :8848`

因此 OpenCode 仍然是本機入口，OpenWorker/go-tool 才是 authority。

### 安全邊界

- OpenCode server 只監聽 `127.0.0.1:4096`。
- OpenCode server 強制 Basic Auth。
- MCP bridge 只監聽 `127.0.0.1:8850`。
- MCP bridge 強制 Bearer Token。
- MCP 不暴露任意 shell。
- MCP 不允許任意 Case；目前只允許 0005。
- MCP 不允許任意 machine；queue clear 只允許 `DESKTOP-ODAQN0D`。
- MCP 不允許 GitHub business execution。
- 遠端不得直接公開 OpenCode 4096 或 go-tool 8848。

## OpenCode 的角色

OpenCode 不是新的總控 authority，只是本機入口/代理。OpenCode 不應直接：

- 決定 Action 執行順序；
- 自己維護 Case 狀態；
- 自己宣稱 Case 成功；
- 搬運成果到 GitHub；
- 取代 WorkLedger / Engineering OS / Drive review gate。

## 本機 REAL 驗證入口

ODA 上應執行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\activate-case0005-opencode-remote.ps1
powershell -ExecutionPolicy Bypass -File scripts\verify-openworker-opencode-bridge.ps1
```

第二條至少驗證：

1. MCP initialize 成功；
2. tools/list 恰好四個工具；
3. `supervisor_status` 經 OpenCode → openworkerctl 成功；
4. `case_status 0005` 經 OpenCode → openworkerctl 成功；
5. 選擇 `-IncludeWriteSmoke` 時才真正跑 `case_continue 0005`。

## 還沒有完成的部分

### A. ODA 實機驗證

目前以上是 source closure，還沒有 ODA 本機執行 receipt，所以不能說 Remote Bridge 已 REAL 成功。

### B. ChatGPT 產品端 Remote MCP 掛載

ChatGPT 不能直接連 localhost MCP。要從 ChatGPT 控制 ODA，還需要受控 Remote MCP tunnel / custom app 掛載。

這是產品/連線層，不應再改 OpenWorker Case authority。MCP tunnel 只應轉發 `127.0.0.1:8850/mcp`，不得轉發 OpenCode 4096 或 go-tool 8848。

目前 ChatGPT 自訂 MCP 的 write/modify 可用性依方案與 developer-mode 權限而異。若目前 ChatGPT 端沒有 write MCP 權限，代碼已就緒也不能假裝本會話能直接呼叫 `case_continue`。
